# Инструкция по сборке, запуску и тестированию
## Лабораторная работа №4 (CUDA), Windows

Данный документ содержит руководство по настройке окружения, компиляции CUDA-программы, запускным параметрам и автоматическому тестированию Лабораторной работы №4 на операционной системе **Windows**.

---

## 1. Требования к окружению

Для успешной работы в Windows вам понадобятся:

* **Компилятор C++**: MSVC (Visual Studio 2022 с рабочей нагрузкой «Разработка классических приложений на C++»).
* **NVIDIA CUDA Toolkit** с компилятором `nvcc`, совместимый с установленной версией MSVC.
* **Драйвер NVIDIA** и видеокарта с поддержкой CUDA. Проект собирается под архитектуру **compute capability 8.6** (например, NVIDIA GeForce RTX 3060 Ti и другие видеокарты семейства RTX 30xx).
* **CMake** (версии 3.30 или выше — этого требует корневой `CMakeLists.txt`).
* **Ninja**.
* **Python 3.8+** (с добавлением в `PATH`).
* **numpy** для автоматического тестирования.

Проверить доступность CUDA и компилятора можно командами:

```PowerShell
nvcc --version
nvidia-smi
```

> Если ваша видеокарта имеет другую архитектуру, измените значение `CMAKE_CUDA_ARCHITECTURES` в `labs/lab_4/CMakeLists.txt` (сейчас там указано `86`).

---

## 2. Главное правило рабочей директории

> **ВАЖНО:** Все команды выполнять в `Developer PowerShell for VS` **строго из корневой папки репозитория** (`Parallel_Programming`), а не из папки `labs/lab_4/`.

Все относительные пути в скриптах и CMake-пресетах завязаны на корень проекта.

---

## 3. Компиляция проекта CMake

```PowerShell
# 1. Конфигурация проекта
cmake --preset windows-release

# 2. Компиляция
cmake --build --preset windows-release
```

CUDA-цель собирается вместе с остальными лабораторными работами. Исполняемый файл появится по пути:

```text
build\windows-release\labs\lab_4\pp_lab_4.exe
```

> Для сборки обязателен установленный CUDA Toolkit: без `nvcc` конфигурация CMake завершится ошибкой.

---

## 4. Запуск C++ программы вручную

Исполняемый файл (`pp_lab_4.exe`) принимает три обязательных позиционных аргумента (пути к файлам) и один необязательный — размер блока:

```PowerShell
.\build\windows-release\labs\lab_4\pp_lab_4.exe <путь_к_matrixA> <путь_к_matrixB> <путь_к_matrixC> [размер_блока]
```

* `размер_блока` — сторона квадратного CUDA-блока: `8`, `16` или `32`. По умолчанию используется `16`.
* Файлы матриц имеют текстовый формат: первая строка — размер `N`, затем `N` строк по `N` чисел.

Пример прямого запуска:

```PowerShell
.\build\windows-release\labs\lab_4\pp_lab_4.exe labs\lab_4\scripts\matrixA.txt labs\lab_4\scripts\matrixB.txt labs\lab_4\scripts\matrixC_res.txt 16
```

Файлы `matrixA.txt` и `matrixB.txt` создаются скриптом тестирования (см. следующий раздел) либо подготавливаются вручную.

Программа выводит размер матрицы, размер блока, суммарное число операций, время выполнения в секундах и производительность в GFLOPS.

---

## 5. Автоматизированное тестирование (`PythonMatrixTest.py`)

Скрипт автоматически собирает проект, генерирует матрицы, запускает CUDA-программу для всех конфигураций, сверяет результат с `numpy` и сохраняет метрики в CSV.

Запуск тестирования:

```PowerShell
python .\labs\lab_4\scripts\PythonMatrixTest.py
```

Скрипт перебирает размеры матриц `N = 128, 256, 512, 1024, 2048, 4096` и размеры блоков `8, 16, 32`. Результаты записываются в:

```text
labs\lab_4\scripts\results_cuda.csv
```

> Тестирование может занять продолжительное время и требует достаточно оперативной памяти для матриц `N = 4096`. При отсутствии `numpy` установите его командой `pip install numpy`.

---

## 6. Генерация графиков (`BuildCharts.py`)

```PowerShell
python .\labs\lab_4\scripts\BuildCharts.py
```

Графики в формате `.svg` будут созданы в папке `labs\lab_4\scripts\figures\`:

* `cuda_time.svg` — время выполнения от размера матрицы для разных размеров блока.
* `cuda_gflops.svg` — производительность (GFLOPS) от размера матрицы.
* `cuda_speedup.svg` — ускорение относительно блока `8 x 8` в зависимости от `N`.
